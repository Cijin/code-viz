Hard limits
01Runtime numbers need a pinned test. Without one, execution stops at static facts.
02Analyze the build that ships: -o:speed with -debug. A debug-only build misreports inlining and checks.
03Optimized code maps to lines only approximately. Inlined code gets the line of its origin.
04Odin on Windows emits PDB, not DWARF. Windows needs a second reader, so Linux and macOS come first.
05Callgrind and DHAT run on Linux only. macOS needs a different T2 backend.
06Go's own compiler is not LLVM. llvm-mca and LLVM passes do not apply to Go.
Glance rules
01Show deltas, not dashboards. Show only what changed since the last green build.
02Color means attention. Orange is cost, blue is gain, grey is no change.
03Shapes, not sentences. Text goes in hover and lenses only.
04Every consequence sits on the row of the code that caused it.
05Use deterministic metrics only: bytes, instruction counts, check sites.
06Silence is the default. A lane with no change collapses to one line.
